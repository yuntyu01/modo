# modo

설치 후 홈 화면·앱 목록·위젯 목록의 앱 이름과 앱 안 로고는 **modo**입니다. 한국어 스토어 이름은 **modo - 메모와 할 일**, 소개 문구는 **떠오른 생각과 해야 할 일을 한곳에.** 영문 스토어 이름은 **modo - Simple Memo & ToDo** (끝에 마침표 없음), 영문 홍보 문구는 **Simple, modern Memo & ToDo.** 이름은 Memo + Do, 메모하고 실행하기. 로고는 받은 시안(파란 m + 체크 심볼과 둥근 글자 modo): 심볼은 시안에 맞춰 다시 그린 벡터 선 경로(`app/src/ui/Logo.tsx`, 시안과 겹침 96.8%), 글자는 시안에서 오린 이미지(`app/assets/brand/modo-wordmark.png`).

영문 스토어 이름은 공백·기호를 포함해 25자로 Google Play의 30자 제목 제한에 맞는다([공식 제목 규격](https://support.google.com/googleplay/android-developer/answer/9859152?hl=en)). 스토어 등록정보를 저장한 것과 실제 게시 완료는 구분한다. 설치 이름은 Expo `name`으로 설정하고 스토어 제목은 Play Console에서 별도로 관리한다. 설치 패키지 식별자는 `com.yuntyu01.naegirok`을 유지한다.

할 일과 메모를 한 화면에서 쓰는 앱. Android·iOS(React Native/Expo), Windows 데스크톱 미니창(Electron), 동기화·공유 서버(Go + PostgreSQL).
모든 기능 무료(개수 제한·Pro·결제·광고 없음).

앱 아이콘은 원래 사용하던 단색 배경의 벡터 심볼 버전으로 복원했습니다. 모바일·Android 적응형/단색·Windows 아이콘도 같은 이전 버전입니다. `app/assets/brand/app-icon-source.png`는 복원한 아이콘 원본입니다.

Android 카카오 로그인은 카카오톡이 있으면 공식 SDK로 인증하고 없으면 기존 웹 로그인을 사용합니다. 네이티브 앱 키는 로컬 `app/.env.local` 또는 빌드의 `MODO_KAKAO_NATIVE_APP_KEY`로 전달합니다(저장소 비밀값). REST/Client Secret/Admin 키는 서버 전용입니다. 서버는 토큰의 앱 ID·만료·회원번호를 카카오에 검증하고 기존 PKCE 일회용 코드로 교환하므로, 웹 로그인 계정과 같은 기록을 사용합니다. 카카오 콘솔에는 패키지 `com.yuntyu01.naegirok`과 Google Play 앱 서명 인증서의 SHA-1 Base64 키 해시를 등록해야 합니다.

```
app/                          Expo(SDK 57) 앱. src/app = 화면, src/core = 로컬 DB·동기화(플랫폼 공통 TS)
app/modules/modo-native       Android(Kotlin)·iOS(Swift) 네이티브: 위젯, 빠른 설정 타일, 빠른 추가, 잠금화면 알림, 리마인더
app/targets/widget            iOS WidgetKit 확장(@bacons/apple-targets)
desktop/                      Windows 미니창(Electron). 화면은 app을 웹으로 내보낸 것(renderer/)
server/                       Go API(net/http + pgx) + PostgreSQL 스키마
docker-compose.yml            로컬 PostgreSQL + 서버
docs/screenshots/             실제 기기·Windows에서 찍은 화면(sheets/ 에 주제별 묶음)
```

## 실행

### 서버(동기화·공유가 필요할 때만, 로컬 사용은 서버 없이 됨)

```bash
docker compose up -d --build          # db(5432) + server(8080)
# 또는 DB만 띄우고 서버는 직접
docker compose up -d db
cd server && go run ./cmd/server
```

| 변수 | 기본값 | 설명 |
|---|---|---|
| `DATABASE_URL` | `postgres://modo:modo@localhost:5432/modo?sslmode=disable` | 서버 DB |
| `PORT` | `8080` | 서버 포트 |
| `EXPO_PUBLIC_API_URL` | `http://127.0.0.1:8080` | 앱 로그인 화면의 서버 주소 기본값(화면에서 바꿀 수 있음) |
| `KAKAO_REST_API_KEY` | - | 카카오 로그인 REST API 키. 비우면 앱에 카카오 버튼이 안 나온다 |
| `KAKAO_CLIENT_SECRET` | - | 카카오 Client Secret. 새 키는 기본 활성화이므로 함께 설정 |
| `GOOGLE_CLIENT_ID` | - | Google OAuth 웹 애플리케이션 클라이언트 ID |
| `GOOGLE_CLIENT_SECRET` | - | Google OAuth 클라이언트 보안 비밀. 두 값이 모두 있어야 Google 로그인 활성화 |
| `PUBLIC_URL` | `http://127.0.0.1:<PORT>` | 외부 로그인 콜백의 서버 주소. 운영 환경은 `https://modo.kodeploy.com` |
| `TRUST_PROXY` | - | `1`이면 리버스 프록시(HTTPS) 뒤로 보고 `X-Forwarded-For`로 접속 주소를 본다(요청 수 제한이 모든 사용자에게 한꺼번에 걸리지 않게) |
| `RATE_LIMIT` | `10` | 로그인·가입·외부 로그인을 접속 주소마다 1분에 몇 번까지 받을지(E2E 테스트 서버는 크게) |
| `TEST_DATABASE_URL` | - | 서버 통합 테스트용 DB(테이블을 지우므로 전용 DB) |
| `SYNC_TEST_SERVER` | - | 앱·데스크톱 동기화 E2E 테스트가 붙을 실서버 |

`app/.env.example` 참고. 실기기는 `EXPO_PUBLIC_API_URL=http://<PC IP>:8080`. Windows에서는 `localhost`가 IPv6로 먼저 풀려 WSL 서버에 안 닿을 수 있어 기본값을 `127.0.0.1`로 둔다.
앱은 자체 호스팅(http) 서버를 위해 평문 통신을 허용한다(`expo-build-properties` `usesCleartextTraffic`). 공개 배포는 HTTPS 서버를 쓰고 이 설정을 끌 것.
Docker 프로젝트 이름은 `modo`로 고정(볼륨 `modo_pgdata`). 예전 `todo_pgdata` 볼륨은 지우지 않고 남겨 두었다(내용은 `modo`로 옮김).

#### 카카오 로그인 설정

1. [카카오 개발자](https://developers.kakao.com) → 내 애플리케이션 → 앱 추가 → **REST API 키**를 `KAKAO_REST_API_KEY`로.
2. 카카오 로그인 활성화, **Redirect URI**에 `<PUBLIC_URL>/api/auth/kakao/callback` 등록(예: `http://192.168.0.10:8080/api/auth/kakao/callback`).
3. 동의 항목: 닉네임(필수 권장), 카카오계정(이메일)(선택). 카카오 로그인은 늘 따로 된 계정이다: 같은 이메일의 비밀번호 계정에 자동으로 붙지 않는다(비밀번호 가입은 이메일을 확인하지 않아, 남의 이메일로 먼저 가입해 둔 사람이 그 계정을 넘겨받을 수 있어서). 이메일이 이미 쓰이고 있으면 카카오 계정은 이메일 없이 만들어지고(이름으로 표시), 공유 초대는 이메일이 있는 계정만 받을 수 있다.
4. 플랫폼 키 → REST API 키의 Client Secret을 `KAKAO_CLIENT_SECRET`로. 새 키는 기본 활성화되어 있다.

Google 로그인 설정, 정확한 운영 리다이렉트 주소, 보관 방식과 검증은 [소셜 로그인](docs/social-login.md)을 참고한다. Google 로그인에는 일반 API 키가 필요하지 않다.

흐름: 앱 → 서버 `/api/auth/kakao/start` → 카카오 로그인 → 서버 `/callback`(토큰 교환·사용자 확인) → `modo://auth?code=…`로 앱 복귀 → 앱이 PKCE verifier와 함께 `/api/auth/exchange` → 세션 토큰. 카카오 키는 서버에만 있고, 앱으로 돌아오는 일회용 코드는 그 기기의 verifier 없이는 쓸 수 없다. 휴대폰은 시스템 인증 브라우저(`expo-web-browser`), Windows는 기본 브라우저와 `127.0.0.1` 임시 콜백을 사용한다. `modo://` 스킴이 새로 들어가서 Android/iOS는 다시 빌드(`npx expo prebuild --clean`)해야 한다.

### Android

네이티브 모듈이 있어 Expo Go가 아니라 개발/릴리스 빌드가 필요하다.

```bash
cd app && npm install
npx expo prebuild -p android
cd android && ./gradlew :app:assembleRelease      # 디버그는 :app:assembleDebug + npx expo start --dev-client
adb install -r app/build/outputs/apk/release/app-release.apk
adb reverse tcp:8080 tcp:8080                      # 에뮬레이터에서 로컬 서버 접속
```

메모리 8GB 이하에서는 ninja가 코어 수만큼 clang을 띄워 OOM이 난다:
`taskset -c 0-5 ./gradlew ... --max-workers=2 -Pkotlin.compiler.execution.strategy=in-process`.

### iOS (macOS + Xcode 16 필요)

```bash
cd app && npx expo prebuild -p ios && cd ios && pod install
# Xcode에서 Signing의 Team 설정 후 앱 + ModoWidget 타깃 빌드
```

App Group `group.com.yuntyu01.naegirok`을 Apple 개발자 계정에 등록해야 앱과 위젯이 같은 DB를 연다. `app.json`의 `ios.appleTeamId`도 채울 것.

### Windows 미니창

```bash
cd desktop && npm install
npm run build                                     # core.cjs(메인 프로세스 동기화 = app/src/core 묶음) + renderer/(app을 웹으로)
npm start                                         # 개발 실행(현재 OS)
scripts/stage-win.sh electron-v44.7.2-win32-x64.zip out/win   # Windows 실행 폴더(Wine 불필요) → out/win/modo.exe
```

## 테스트

```bash
docker compose exec db psql -U modo -c 'CREATE DATABASE modo_test'
cd server && TEST_DATABASE_URL='postgres://modo:modo@localhost:5432/modo_test?sslmode=disable' go test ./...
cd app && SYNC_TEST_SERVER=http://127.0.0.1:8080 npx jest       # 로컬 DB + 두 기기 동기화 E2E
cd app && PERF_SERVER=http://127.0.0.1:8080 npx jest perf        # 속도 측정(할 일 2000·문단 2000, 기본은 건너뜀)
cd app && npx tsc --noEmit
cd desktop && SYNC_TEST_SERVER=http://127.0.0.1:8080 npm run test:sync   # Electron node:sqlite 저장소로 두 PC 동기화
cd desktop && npm run test:unit                   # 데이터 폴더 옮기기(지정 프로필·있는 폴더를 건드리지 않음), 메인 프로세스 동기화(창 변경 보내기·받은 변경 알림·오프라인 뒤 재전송·빈 동기화 무알림·마이그레이션 전 백업)
```

## 모바일 자동 배포 (비공개 테스트)

`master`에 앱(`app/`) 변경을 푸시하면 GitHub Actions(`.github/workflows/mobile-release.yml`)가 돈다.

1. **checks**: 타입·린트·테스트.
2. **android**: 기존 업로드 키(저장소 비밀값 `MODO_UPLOAD_*`, PR #1의 `plugins/withReleaseSigning.js`)로 AAB를 빌드하고 Google Play **비공개 테스트**(API 트랙 `alpha`)의 출시를 새 번들로 바꾼다(`.github/scripts/play_release.py`). 버전 코드는 Play에 있는 가장 큰 값 + 1(사용자에게 보이는 버전 `expo.version`은 직접 올린다). 이전 출시의 국가 제한은 이어 받는다. 만든 AAB는 Actions 아티팩트로 14일 남는다.
3. **ios**: 저장소 변수 `IOS_RELEASE=true`일 때만. EAS에서 빌드하고 끝나면 TestFlight로 자동 제출(`eas build --auto-submit`, `app/eas.json`, 빌드 번호는 EAS가 올린다).

- 연달아 푸시하면 앞의 실행은 멈추고 마지막 것만 올린다. `desktop/`·`server/`만 바뀐 푸시, 커밋 메시지에 `[skip ci]`가 있는 푸시는 돌지 않는다. Actions 탭에서 손으로 돌릴 수도 있다.
- Google 검토가 필요한 변경이면 검토가 끝난 뒤 테스터에게 간다. 자동으로 검토에 보낼 수 없는 상태면 올려만 두고 경고를 남긴다(Console에서 '검토를 위해 변경사항 보내기').

처음 한 번 할 일(계정·키, 사람이 직접):

- **Android**: Google Cloud에서 서비스 계정을 만들고 JSON 키를 받는다 → Play Console 사용자 및 권한에서 그 계정(이메일)을 초대해 이 앱의 출시 권한(테스트 트랙 출시 관리)을 준다 → `gh secret set PLAY_SERVICE_ACCOUNT_JSON < 키.json`. 이 비밀값이 없으면 AAB만 만들고 Play에는 올리지 않는다.
- **iOS**(Apple Developer Program 가입 뒤)
  1. `cd app && npx eas-cli@latest login` → `npx eas-cli@latest init`(app.json에 projectId가 생김, 커밋). `app.json`의 `ios.appleTeamId`에 팀 ID.
  2. 처음 한 번은 직접 `npx eas-cli@latest build -p ios --profile production`(Apple 로그인 → 앱·위젯(ModoWidget)·App Group 인증서와 프로필을 EAS가 만든다)과 `npx eas-cli@latest submit -p ios`(App Store Connect 앱과 API 키). App Store Connect 앱의 Apple ID를 `app/eas.json`의 `submit.production.ios.ascAppId`에.
  3. expo.dev → Access tokens에서 토큰 → `gh secret set EXPO_TOKEN`, `gh variable set IOS_RELEASE --body true`.
  - iOS는 아직 한 번도 빌드해 보지 않아(위젯 Swift 포함) 첫 빌드에서 고칠 것이 나올 수 있다.

## 구현한 것

- 화면 디자인 D(시안 11장 기준, 같은 dp로 나란히 놓고 맞춤, docs/screenshots/sheets/7·8):
  - 캘린더: 맨 위 작은 로고 → 가운데에 제목처럼 쓰는 '2026년 10월'(⌄ 없이, 누르면 연·달 고르기, 다른 달·날을 보고 있으면 오른쪽 '오늘') → 달력 카드(좌우로 밀어 한 달씩, 넘어간 방향에서 미끄러져 들어온다. '캘린더' 제목과 ‹ ›는 두지 않는다 — 사용자 요청 2026-10-18; 앞뒤 달 날짜 흐리게, 고른 날 강조색 원, 할 일 있는 날 점) → '10월 17일 토요일' + 그날 할 일(폴더 이름 강조색) → '할 일 추가'(누르면 그 자리가 입력칸, 엔터로 고른 날짜의 할 일을 만들고 이어 쓰기, 오른쪽 폴더 이름을 눌러 저장 폴더 변경) → 날짜 없는 할 일(오른쪽 '날짜 지정').
  - 설정: 로고 머리 → 내 계정 카드 → 화면과 위젯(꾸미기·위젯 설정) → 할 일(아래에 추가·완료한 할 일 접기) → 언어·도움말. 휴지통·백업·잠금화면은 ⋯ 메뉴, 잠금화면은 위젯 설정 안에도.
  - 꾸미기: 미리보기 → 테마 색상 6개 → 화면(시스템/라이트/다크) → 글자 크기·체크 위치·배경 그라데이션 → 위젯·미니창 투명도(기본 80%). 직접 고르는 색·카드색·서체·굵기·개별 위젯/미니창 테마는 '더 많은 꾸미기'.
  - 공유: 초대(이메일·권한·초대하기) → 함께하는 사람(나 소유자, 권한 바꾸기·내보내기) → 링크 공유(보기 전용 링크 켜기/끄기·복사) → 공유 중지.
  - 홈 위젯(Android·iOS): 맨 위 한 줄에 왼쪽 로고(글자 없이, 누르면 앱)와 앱과 같은 폴더 탭(기본 + 폴더들, 지금 폴더는 굵은 흰 글자, 누르면 그 폴더의 첫 쪽으로. 폭이 모자라면 지금 폴더 근처만). 첫 쪽은 그 폴더 메모만(미리보기, 넘치면 마지막 줄 …), 다음 쪽부터 할 일만(상자·구분선 없이, 빈 원/반복 원 + 제목 아래 '매일 · 오늘'. 제목은 한 줄, 넘치면 … — 제목만인 줄은 두 줄이 줄 높이 안에 들 때만 두 줄). 아래 가운데 쪽 점(메모 쪽 1 + 할 일 쪽 수, 한 쪽이면 숨김, 점 사이 20dp, 마지막 할 일 바로 아래), 할 일 쪽에서만 오른쪽 아래 +. 파란 기 없는 차콜 반투명 바탕. 잠금화면에 놓인 Android 위젯은 예전 전용 레이아웃(동그란 ‹ ›, 메모와 할 일 사이 선) 그대로.
  - 모서리: 시안 원본에서 원 맞추기로 잰 값(할 일·설정 묶음·공유 카드 14~14.5, 메모·달력·꾸미기 미리보기 16, 화면 세그먼트 18, 위젯 19, PC 미니창 15.5). 할 일·메모 카드와 캘린더의 달력 카드는 바탕이 은은하게 비친다(다크 80%, 테마색 쪽으로 살짝).
  - 하단바와 홈 입력창은 따로 자리를 차지하지 않고 내용 위에 떠 있다(양옆·아래로 목록이 비치고 옅은 그림자). 목록·캘린더·더보기는 화면 바닥까지 그리고 스크롤 끝에 하단바(+입력창) 높이만큼 여백을 둬 마지막 항목을 위로 올릴 수 있다(`useBottomInset`). 키보드가 열리면 하단바는 숨는다.
  - 휴대폰 홈 아래(화이트 시안): 입력창은 할 일 카드와 같은 높이(62.5, PC 48)의 알약(할 일 모드면 토글 뒤 지름 39의 옅은 테마색 동그라미), 하단바는 입력창과 같은 너비(양쪽 19) · 높이 49.4의 알약, 고른 탭은 테마색 아이콘 + 옅은 테마색 알약(65×38). 둘 다 그림자·테두리 없이 옅은 회청색 유리(#EEF2F8 / #EDF3F8). 라이트 바탕은 거의 흰색 #F7F9FC, 위쪽은 아주 옅은 하늘빛에서 화면 40%쯤 흰 바탕으로, 할 일·메모 블록은 불투명한 흰색. 홈 카드 사이 10. 휴대폰은 홈 요소(로고·폴더 이름·메모·할 일 카드·입력창)를 시안 치수보다 5% 크게 그린다(theme.zoom, 사용자 요청). 할 일 카드는 캘린더·전체 보기도 같은 카드라 함께 커진다. PC 큰 창은 PC 시안대로 창 아래에 붙은 줄(아이콘 + 이름).
  - PC 큰 창: 제목줄 없이 창 버튼이 그라데이션 위에 겹치고, 가운데 좁은 단(481, 카드 폭 446), 카드 안 글자·동그라미는 시안대로 휴대폰보다 조금 크게, 머리에 검색·공유(서버에 닿을 때만)·미니창 열기·⋯, 좁은 하단바. 스크롤 막대는 기본 막대를 숨기고 마우스를 올린 목록에만 3px 막대를 띄운다(`ui/thinScrollbar.ts`, 윈도우 크롬 152는 `::-webkit-scrollbar` 꾸미기를 무시해 8~10px로 남았다). 미니창(기본 폭 348): 로고·고정·최소화·닫기 / 폴더 탭 / 메모, 아래 남은 할 일 카드와 입력창(체크 토글). 완료한 할 일은 위젯처럼 미니창에서 빠지고 큰 창에서 본다. PC 글꼴은 Pretendard(app/public/fonts, OFL).
- 홈 디자인(최신 시안 기준, 같은 dp로 나란히 놓고 맞춤): 로고(심볼 + modo) 제목, 카드 높이 60·동그라미 28·글자 17(Android는 한글 글꼴이 크게 그려져 홈 글자만 0.87배), 날짜·시각은 '내일 · 17:00', 완료 항목은 머리글 없이 목록 아래, 입력창 높이 50·하단바 59(반복 시안), 기본 강조색은 대표색 #85ADE2(아래 '대표색'), 위쪽 남색 그라데이션은 시안보다 진하게(사용자 요청), 화면 2/3쯤에서 바탕색.
- 이름·로고: 앱 이름 modo, 홈 화면 제목은 로고(심볼 + modo), 앱 아이콘·빠른 추가 아이콘(심볼 + +)·시작 화면·PC 아이콘도 같은 로고, 더보기 아래 한 줄 소개. 패키지 ID(`com.yuntyu01.naegirok`), Kotlin 패키지(위젯 연결), DB 파일 이름(`naegirok.db`), 링크 주소 `naegirok://`는 설치·데이터·위젯 연결을 지키려고 그대로 둔다. 코드·폴더 이름은 modo(`modules/modo-native`, Go 모듈 `github.com/yuntyu01/modo/server`, Docker `modo`), 새 링크 주소 `modo://`도 함께 받는다.

- 메모는 하나의 문서(내부는 안정 ID 문단). 메모 모드로 쓰면 메모 끝에 문단이 붙고 새 카드가 생기지 않는다. 문단 안 엔터 = 문단 나누기, 맨 앞 지우기 = 합치기.
- 폴더 하나마다 메모 문서 하나 + 그 폴더의 할 일. 화면 순서: 로고(modo) → 폴더 선택(기본·폴더들·+) → 그 폴더의 메모 → 그 폴더의 할 일 → 입력창 → 하단 내비. 폴더를 바꾸면 메모와 할 일이 함께 바뀐다.
- '기본' 폴더 = 폴더 ID가 없는 항목(예전 미분류). 실제 폴더 행을 만들지 않아 기기마다 기본 폴더가 따로 생겨 겹치지 않고, 기존 데이터는 옮기거나 복제하지 않는다. 없어진 폴더를 가리키는 항목도 기본에 보인다. 첫 실행은 기본, 그 뒤엔 이 기기에서 마지막으로 쓴 폴더(지워졌거나 공유가 끊기면 기본).
- 검색: 머리의 돋보기를 누르면 폴더 줄 자리에 검색창이 뜨고 폴더 줄은 한 줄 아래로 내려간다(지금 폴더 안에서 찾고, 폴더를 바꾸면 그 폴더에서). Esc·×로 닫는다. (예전 '전체 할 일 보기'는 없앴다.)
- 할 일 카드(휴대폰·PC 큰 창·미니창 같은 규칙, `ui/format.ts` `cardWhen`·`repeatShort`):
  - 생김: 왼쪽 체크 원, 제목(약 16), 아래 보조 줄 하나(12~12.5, 회색). 보조 줄은 주기 · 날짜·시간이다.
  - 체크 원: 일반은 빈 원, 반복은 같은 크기·굵기의 원을 시계 방향 두 곡선 화살표로(가운데 비움, 작은 화살촉이 테두리 밖으로 살짝, `Icons.tsx` `RepeatRingIcon`), 완료는 테마색 + 흰 체크. Android 홈 위젯은 같은 모양의 `naegirok_check_repeat.xml`, iOS 홈 위젯은 같은 수치로 그린 `RepeatRing`(잠금화면 위젯은 SF Symbol `arrow.triangle.2.circlepath`).
  - 주기: '매일', '월·수·금', '평일', '주말', '매주 목요일', '매월 16일'.
  - 날짜: 오늘·내일은 말로, 올해는 '10월 19일', 다른 해는 연도까지 쓴다. 반복은 이번 회차 예정일이다.
  - 시간: 알림을 정한 때만 '오후 8:00'.
  - 표시 규칙:
    - 없는 정보는 빼서 빈 구분점·빈 줄이 남지 않는다. 기한이 지난(완료 안 한) 할 일은 날짜와 며칠 지났는지가 빨간색이다: '10월 16일 · 2일 지남'(위젯도 같다, `format.ts` `cardLate`).
    - 카드 최소 높이·사이 간격: 미니창 52·6, PC 큰 창 60·8, 휴대폰 64·8(dp, 화면 배율 1.05는 곱하지 않음). 고정 높이가 아니라 최소 높이라 긴 제목·줄바꿈·시스템 글자 확대 때는 늘어난다.
    - 정보가 있든 없든 기본 높이는 같다: 동그라미와 글 묶음(제목, 또는 제목 + 보조 줄)을 세로 가운데에 둔다. 제목과 보조 줄 사이는 0(줄 높이 안의 글자 여백만, 보이는 간격 6~8 — 4였을 때 10~12로 벌어져 보여 줄임, 홈 위젯도 같다). 위아래 여백은 기본 글자 크기에서 두 줄 묶음이 최소 높이 안에 들어가게 계산한다.
    - 동그라미 크기·왼쪽 자리, 제목 시작 자리, 좌우 여백은 모든 카드가 같다(캘린더의 '날짜 지정'이 붙은 카드도). 입력창·캘린더 '할 일 추가' 칸 높이는 그대로 둔다.
    - 긴 제목: 날짜·반복 줄이 있으면 1줄, 없으면 2줄까지 보이고 넘치면 '…'. 잘린 제목을 처음 누르면 여러 줄로 펼치고, 펼친 뒤 누르면 그 자리에서 고친다(고치고 나면 다시 접힌다)(그래서 보통 글자 크기에선 긴 제목 카드도 같은 높이). PC는 잘린 제목에 마우스를 0.5초 올리면 전체 제목 말풍선(우상단 아이콘 말풍선과 같은 색, 카드 글 아래, 자리가 없으면 위, `ui/textTip.web.tsx`). 누르면 펼쳐진다: 고칠 수 있으면 전체 글로 편집, 보기 전용이면 펼치기/접기.
    - 좁은 창·큰 글자에서는 보조 줄 안에서 줄을 바꾼다.
    - 달성 점·연속 횟수는 카드에서 뺐다(캘린더에서 본다).
  - 주기 글자를 누르면 반복 설정이 열리고, 완료·제목 편집으로 넘어가지 않는다. 반복 동그라미는 다른 동그라미처럼 완료다.
- 입력창:
  - 휴대폰: 지금 모드 아이콘 하나(할 일 = 체크 상자, 메모 = 메모지)를 보인다.
    - 누르면 모드가 바뀌고 바로 그 입력칸에 커서가 간다.
    - 키보드가 닫혀 있으면 열리고, 열려 있으면 그대로 둔다. 뒤로 가기로 키보드만 내린 경우도 다시 연다.

- 목록 맨 아래 '완료 항목 보기 · N' / '완료 항목 숨기기' 글자 버튼(숨길 수 있는 완료 항목이 있을 때만, 루틴은 늘 보인다). 휴지통의 복원·삭제는 블록 없이 글자만.
- 서버(API): 앱이 `/api/auth/providers`로 서버에 닿는지 1분마다·앞으로 올 때마다 확인한다(`AppContext.serverApi`). 닿지 않으면 공유·내 계정·계정 공유처럼 서버가 있어야 하는 것은 숨기고 이 기기에서만 쓴다. 닿고 아직 로그인하지 않았으면 처음에 로그인 화면(카카오로 계속하기, 서버가 켜 두었으면 이메일 로그인, '나중에'는 이번 실행 동안만)을 띄우고, 로그인하면 늘 동기화한다(`ui/LoginGate.tsx`).

- 입력창 맨 오른쪽 체크 토글 하나(켜면 할 일, 끄면 메모 이어 쓰기). 할 일 모드는 실선 미리보기 카드, 메모 모드는 이어 쓸 위치(깜빡이는 커서)를 보여주고 저장하지 않는다. 초안은 폴더·모드마다 따로 보관(이 기기에 저장, 재시작해도 남음)해 다른 폴더에 잘못 저장되지 않는다. 토글을 바꿀 때 바꾼 쪽 초안이 비어 있으면 쓰던 글을 그대로 가져간다. 한글 조합 중 엔터·연속 제출 중복 방지. 첫 사용 때만 안내.
- 글자를 누르면 그 자리에서 편집(커서 위치 유지), 동그라미를 누를 때만 완료. 완료하면 잠깐 체크가 보인 뒤 아래 '완료 N' 묶음(최근 완료 순, '완료 비우기' + 실행 취소)으로 내려간다. 읽는 상태 길게 누르기 = 정보 시트(PC는 오른쪽 클릭 또는 왼쪽 버튼 0.5초 누르기 — 할 일 카드는 제목·보조 줄·빈 곳 어디든, 동그라미·반복 주기 버튼 제외, `ui/webLongPress.ts`. 완료한 할 일은 완료 시각을 맨 위에, 만든·고친 시각, 폴더, 예약 날짜, 알림, 반복), 길게 누른 채 끌기 = 순서 바꾸기(휴대폰 홈·PC 미니창). PC 미니창은 창 높이가 내용을 따라가서, 시트(정보·날짜·알림·반복·폴더)를 여는 동안 창을 600까지 잠깐 키우고(화면 아래를 넘으면 그만큼 위로) 닫으면 원래 높이·자리로 돌아간다. 편집 중 길게 누르기 = OS 글자 선택(테마색 하이라이트).
- 자동 저장(0.5초 묶음 + 백그라운드 전환 때 즉시). '마지막 수정'은 글이 실제로 바뀔 때만.
- 분류·날짜·알림·반복·공유·삭제는 정보 시트 안에만. 삭제 실행 취소 + 휴지통 복원/영구 삭제. 휴대폰은 할 일 카드를 왼쪽으로 카드 폭의 35% 넘게 밀거나 빠르게 튕기고 놓으면 바로 지우고, 오른쪽으로 25% 넘게 밀면 정보 시트를 연다(미는 동안 카드가 비켜난 자리에 지우기는 빨간 바탕 + 휴지통, 정보는 회색 바탕 + i가 드러난다)(버튼을 누를 필요 없음, 실행 취소 알림). 미는 동안 카드만 따라오고 지울 만큼 밀면 살짝 작아지며 짧게 진동, 놓으면 카드가 휴지통이 든 ⋯(홈 오른쪽 위, 그 메뉴에 휴지통 · N)로 휘어 날아 들어가고 ⋯가 한 번 튄다(`ui/trashFlight.tsx`, 머리에 ⋯가 없는 캘린더는 하단바 ⋯ 탭으로). 가로로 14dp 넘게 움직였을 때만 시작하고 세로로 먼저 움직이면 포기해 스크롤·길게 눌러 끌기·글자 편집과 겹치지 않는다. 편집 중·끄는 중·보기 전용 카드는 밀리지 않고, 화면 읽기 프로그램은 동그라미의 '삭제' 동작으로 지운다. PC는 마우스 끌기가 글자 선택과 겹쳐 넣지 않았다(오른쪽 클릭 메뉴).
- 반복 할 일(반복 시안): 정보 시트 → '반복' → 아래에서 올라오는 반복 설정 시트(반복 안 함/매일/매주/매월, 매주면 요일, 시작일, '적용하기'). 카드에는 반복 동그라미(두 곡선 화살표, 위 '할 일 카드' 참고)와 주기 '매일', '월·수·금', '매주 목요일', '매월 16일'(홈 위젯도 같은 동그라미·같은 보조 줄 문구: Android `widget/CardMeta.kt`, iOS `Widgets.swift` `CardMeta`). 시작일부터 보이고, 동그라미를 누르면 완료로 남지 않고 다음 예정일로 넘어가 그날 다시 나타난다('다음 예정: 10월 19일 (월)' + 실행 취소). 밀린 날은 건너뛰고, 알림이 있으면 같은 시각으로 함께 옮긴다. 한 날은 `todos.done_log`('YYYY-MM-DD,…', 최근 400일)에 남는다: 앱·Android/iOS 위젯 체크 모두 기록하고, 서버는 기기마다 보낸 추가·삭제를 합친다(`kDateSet`, 두 기기가 다른 날을 체크해도 지워지지 않음). 캘린더는 한 날마다 테마색 점, 지난 날짜를 누르면 그날 할 차례였던 루틴을 했는지(체크/빈 동그라미, 보기만) 보여 준다. 캘린더는 다음 예정일 뒤로도 규칙에 맞는 날마다 점과 카드(미리 보기)를 보여 준다. 위젯·잠금화면 알림·알림의 '완료'도 같은 규칙(Android Kotlin, iOS Swift에 같은 계산).
- 캘린더(예약/날짜 없는 할 일 구분, 날짜 지정, 고른 날짜에 바로 할 일 추가), 검색, 완료 항목 표시/숨기기, 새 할 일 위/아래 추가, 리마인더(절대 시각 저장 → 시간대가 바뀌어도 같은 순간).
- 꾸미기: 테마색 프리셋(흰색·검정 포함)+사용자 지정, 그라데이션 강도, 다크/라이트/시스템, 카드색, 체크 위치, 서체·굵기·크기, 위젯·미니창 테마(앱 따르기/개별)와 배경 투명도. 실제 데이터로 미리보기. 대비가 모자란 색은 자동 보정.
- 언어: 시스템/한국어/English/日本語/简体中文. 앱 화면(`app/src/i18n.ts` ko·en, `app/src/locales/ja.ts`·`zh.ts`), 날짜·요일·반복 표기(`app/src/ui/format.ts`), Android 위젯·빠른 추가·알림(`res/values`, `values-en`, `values-ja`, `values-zh`, 날짜·반복은 `Repeat.kt`의 `Words`), iOS 위젯·알림(`NotesStore.swift`의 `L`), Windows 트레이 메뉴, 서버 오류(서버는 고정 `code`를 보내고 앱이 `err_<code>` 문구로 바꿔 보여 줌), 서버가 그리는 공유 링크·로그인 오류 페이지(브라우저 `Accept-Language`). '시스템'이면 기기 언어 중 지원하는 첫 언어, 없으면 영어(위젯도 같은 규칙). 새 언어는 `LANGS`에 코드를 더하고 `locales/<code>.ts`(모든 키, 빠지면 `tsc`가 잡음)와 위 네이티브 표를 채운다. iOS 단축어 동작 이름(App Intent 제목)은 아직 한국어.
- 첫 실행(휴대폰, `ui/onboarding/Welcome.tsx`): 로고 · '나만의 모도를 시작해요' · 예시(메모 한 칸, 끝낸 할 일) · 테마색 6개(누르면 바로 위쪽 그라데이션·로고 색이 바뀐다) · 첫 번째 할 일(꼭 적어야 시작, 비우고 누르면 칸이 흔들리고 입력이 열린다) · 시작하기. 시작하면 그 할 일을 저장하고 홈 안내(`CoachOverlay.tsx`): 주변을 어둡게 하고 강조 테두리가 적던 칸에서 홈의 그 할 일로, 다음 입력창으로 옮겨 가며 말풍선으로 알려 준다. '이미 계정이 있어요'(서버가 닿을 때)는 로그인 화면으로, 로그인하면 건너뛴다. 예전 버전 사용자(설정·데이터가 이미 있으면)는 보이지 않는다.
- 움직임(`ui/motion.ts`): 하단바·나눔 선택(시스템/라이트/다크)의 고른 바탕이 새 칸으로 흐르듯 미끄러지고(가로로 잠깐 늘었다 탄성 있게 멈춤), 새로 고른 하단바 아이콘이 살짝 튄다. 캘린더 달 넘기기·폴더 바꾸기는 옆에서 미끄러져 들어온다.
- 앞날에 시작하는 반복 할 일(매월 20일 등)도 목록·미니창·위젯에 보이고 아래 줄에 '매월 20일 · 10월 20일'(예전엔 그날까지 캘린더에서만 보여 만든 할 일이 사라진 것처럼 보였다).
- 체크·반복 동그라미: 휴대폰 22.5 · PC 큰 창 19 · 미니창 18(원래 작아 그대로) · 홈 위젯 20(예전보다 약 20% 작게, 테두리도 얇게. 반복 동그라미는 화살촉 끝까지 빈 동그라미와 같은 크기 안에, 사용자 요청 2026-10-18). 폴더 이름은 약 10% 작게(고른 폴더 굵기 그대로), 폴더 옆 +는 글자 높이쯤으로.
- 무채색 테마: 그라데이션은 밝기를 따라(화이트 은빛 · 그레이 중간 · 차콜 은은하게 · 블랙 거의 없이). 바탕과 같은 무채색(라이트의 화이트, 다크의 블랙)은 버튼·선택 표시·로고를 회색으로 흐리지 않고 반대쪽 무채색(검정/흰색)으로. PC 미니창 색(바탕·카드·입력칸·글자·그라데이션)은 앱과 똑같다(예전엔 미니창만 회색 바탕·카드라 푸른 회색으로 보였다). 창 투명도만 미니창 설정.
- 설정(더보기)의 위젯 항목 이름은 '홈·잠금화면'(위젯·빠른 설정 타일·잠금화면이 한 화면에 있어서).

- 위젯·빠른 설정 타일·잠금화면 '직접 넣는 방법'(`settings/howto/[topic]`, 그림 `ui/HowToArt.tsx`): 단계마다 테마색·다크/라이트를 따르는 휴대폰 그림(누를 곳·끄는 방향 표시) + 설명, 4개 언어. 앱에서 바로 추가가 안 되는 런처·기기면 알림 대신 이 화면으로 간다. 위젯 설정 화면의 '직접 넣는 방법'과 잠금화면 화면(지원·가능 기기)에서도 연다.

- Windows: 선택한 폴더의 메모창 + 바로 아래 그 폴더의 할 일 카드가 한 창(함께 이동), 폴더 선택(메모와 할 일 모두에 적용)·고정·더보기·닫기, 크기 조절, 항상 위, 위치·크기·최대 높이 기억, 화면 밖이면 다시 안으로(모니터 분리·DPI 변경), 트레이 숨김/복원, 로그인 시 실행, 백업 저장/열기.
- 동기화: 로컬 우선, 오프라인 큐(같은 항목 연속 수정 합침), op_id로 중복 방지, 지수 백오프 재시도, 삭제(휴지통·영구 삭제) 동기화, 동시 수정은 덮어쓰지 않고 '충돌 사본'으로 보존, 편집 중 항목은 원격 반영을 미룸. 로그인 전 기록은 로그인하면 그대로 올라감. 백업·내보내기·가져오기(중복 없이 병합).
- 공유: 선택 문단/할 일/폴더를 텍스트로 시스템 공유(데스크톱은 클립보드), 계정 초대(보기/편집, 권한 변경, 해제), 보기 전용 링크(그 폴더만). 서버가 소유자·권한을 검증.

## 데이터 구조(정규화)

한 사실은 한 곳에만 둔다. 2026-10-17에 남아 있던 파생 값·쓰이지 않는 열을 걷어 냈다(서버·앱 모두 예전 DB를 열면 자동으로 옮김).

서버(PostgreSQL)
- 계정: `users`(id, 이메일(없을 수 있음), 표시 이름) / 로그인 수단마다 표를 나눔: `password_logins`(비밀번호 해시), `oauth_identities`(공급자 + 공급자 안의 사용자 번호 → 사용자, 카카오) / `sessions`(토큰 해시) / 외부 로그인 진행 중 상태 `oauth_states`(10분)·일회용 코드 `login_codes`(2분).
- 내용: `folders`, `todos`, `paragraphs`: 안정 UUID, `position`(분수 인덱스 문자열), 생성·수정·삭제(휴지통) 시각(epoch ms), 변경 순번 `seq`(pull 커서).
- **항목의 주인은 한 곳에서만**: 폴더에 든 항목은 폴더의 주인(`folders.owner_id`), 기본 폴더(`folder_id` 없음) 항목만 `owner_id`를 직접 가진다. `CHECK ((folder_id IS NULL) <> (owner_id IS NULL))`로 둘 중 하나만 있게 막고, `folder_id`는 `folders` 외래키. (예전에는 폴더 주인을 항목마다 복사해 두고 트리거로 맞췄다.) 항목이 폴더보다 먼저 서버에 가지 않게 앱 큐가 순서를 지키고(폴더로 옮기는 변경은 앞 op에 합치지 않음), 그래도 없는 폴더로 온 새 항목은 내용을 잃지 않게 기본 폴더에 둔다.
- **영구 삭제는 `tombstones`**(id, 종류, 폴더/주인, seq): 내용 행은 지우고 '지웠다'는 사실만 남겨 다른 기기·공유받은 사람이 pull로 받는다. 같은 id로 다시 '만들기'가 와도 살아나지 않는다. (예전에는 내용을 비운 행에 `purged` 표시를 달아 모든 열이 의미 없는 값으로 남았다.) 충돌 사본의 `conflict_of`는 원본이 지워지면 비워진다(FK `ON DELETE SET NULL`).
- 아무도 읽지 않던 `version` 열은 없앴다(변경 추적은 `seq`).
- 완료 여부는 `done_at IS NOT NULL`로만. 반복은 `repeat_freq`(daily/weekly/monthly)·`repeat_days`(매주 요일 비트) 두 열(CHECK로 범위 제한, 다음 예정일은 `due_date`). 두 열 사이 조건은 걸지 않는다(필드별로 동기화돼 잠깐 어긋날 수 있음).
- 공유: `folder_members`(폴더·사용자·권한), `share_links`(토큰·폴더). 재전송 기록 `applied_ops`(30일).

앱(SQLite, 위젯·빠른 추가와 같은 파일)
- `folders`·`todos`·`paragraphs`에 주인·version·purged 열이 없다. 남의 것 = 공유받은 폴더(`shared_folders`: 폴더·권한·주인 id)와 그 안의 항목. 주인의 이메일·이름은 `people`에 한 번만.
- 영구 삭제한 행은 바로 지우고 `outbox`의 op만 남긴다(아직 서버에 안 간 항목이면 op째 버린다).
- `outbox`는 바뀐 필드의 이전값/새값(JSON). `kv`는 기기별 설정. 로컬 `folder_id`에는 외래키를 걸지 않는다(동기화로 항목이 폴더보다 먼저 들어올 수 있음).
- 앱이 새 스키마 버전으로 올라가면 동기화 커서를 처음으로 돌려 한 번 다시 받는다. 위젯(Kotlin/Swift)은 DB를 열 때마다 `purged` 열이 아직 있는지 보고 쿼리를 맞춘다(앱이 옮기기 전에 위젯이 먼저 열 수 있어서).

정렬 키(`position`): 정수부(첫 글자가 길이) + 소수부 방식으로 바꿨다. 맨 뒤/맨 앞에 붙일 때 정수부를 1씩 올리고 내려 1만 개를 붙여도 4자다. 예전 방식은 6개마다 한 글자씩 길어져 **1200개쯤 붙이면 서버 한도(200자)를 넘었고 그 항목들은 서버가 거절해 다른 기기로 가지 않았다**(측정 중 발견: 할 일 2000개 중 1000개만 전달됨). 앱이 열릴 때 64자를 넘는 키가 있으면 순서 그대로 다시 매기고, 200자를 넘어 서버에 없던 항목은 지금 내용으로 다시 올린다. 예전 키와 섞여도 문자열 순서만 쓰므로 그대로 정렬된다. Kotlin(`Frac.kt`)과 TS(`frac.ts`)가 같은 입력에 같은 키를 내는지 대조했다.

## 출시 전 성능·구조 정리 (2026-10-18)

### 구조(바꾼 것)

- **PC 동기화는 Electron 메인 프로세스 한 곳**(`desktop/sync-host.cjs` + `desktop/core.cjs` = `app/src/core` 묶음, `npm run core`).
  - 예전: 미니창·큰 창이 각자 앱 전체(동기화 엔진·서버 확인·테마색 맞추기·30초 타이머)를 돌렸다. 같은 요청이 창 수만큼 나갔고, 미니창을 숨기면(트레이) 동기화가 멈췄다.
  - 지금: 창은 IPC로 상태를 받고 명령만 보낸다(`app/src/native/desktopSync.ts`, `SyncApi`).
  - 주기: 보이는 창이 있으면 30초, 모두 숨으면 5분. 창을 다시 보이면 바로 한 번.
  - 창이 고친 내용은 메인이 DB 커밋(outbox)을 보고 알아서 보낸다.
  - 휴대폰은 같은 코어의 `SyncEngine`을 그대로 쓴다.
- **창은 outbox를 건드리지 않는다**(`repo.init({ owner: false })`). 메인이 보내는 중인 op의 inflight를 새로 연 창이 풀면, 이미 보낸 op에 새 변경이 합쳐져 사라질 수 있었다. 스키마 고치기는 메인이 창보다 먼저 한 번만 한다.
- **바뀐 표만 다시 읽기**: `Repo.write`가 실제로 바꾼 표를 알리고(`Listener(source, tables)`), 화면은 그 표만 다시 읽는다(`snapshot(tables)`).
  - kv·outbox만 바뀐 쓰기(커서·설정·화면 상태)는 화면 갱신·위젯 갱신·다른 창 알림을 하지 않는다.
  - 같은 값으로 고치면 알리지 않는다.
- **빈 동기화는 쓰지 않는다**:
  - 커서가 같으면 저장하지 않는다.
  - 공유 목록·남의 항목이 그대로면 공유 표를 지우고 다시 넣지 않는다(`sweepForeign` 읽기 먼저).
  - 동기화 상태가 같으면 알리지 않는다.
  - 동기화 상태는 따로 둔 컨텍스트(`useSyncStatus`)라, 상태가 바뀌어도 상태를 보여 주는 화면만 다시 그린다. 예전에는 30초마다 앱 전체 카드가 다시 그려졌다.
- **서버 pull의 남의 항목 목록 요약**: 클라이언트가 지난번 요약을 `fd`로 보내고 같으면 서버가 `foreign_ids` 대신 `foreign_same`만 준다. fd를 보내지 않는 예전 앱은 늘 목록을 받는다(`TestForeignDigestSkipsUnchangedList`).
- **목록 그리기**:
  - PC 큰 창 할 일 목록은 가상화(`HomeList.web.tsx` FlatList).
  - 접힌 메모는 보이는 8문단만 그린다.
  - 미니창은 메모 문단·할 일을 40개씩(끝에 가까워지면 더) 그린다.
- **PC 앱 실행**:
  - 하나만 실행된다(두 번째 실행은 0.4~0.7초 안에 끝나고 기존 미니창을 보인다).
  - 로그인 시 실행은 `--autostart` 인자를 붙여 등록한다. 예전 방식(인자 없음)으로 켜 둔 사람만 같은 설정으로 다시 등록하고, 꺼 둔 사람은 그대로 둔다.
  - 자동 실행이면 지난번 미니창 보임 여부대로(트레이만이었으면 트레이만) 시작하고, 첫 동기화·서버 확인은 8초 뒤로 미룬다(직접 켜면 1.5초).
  - 큰 창은 처음부터 만들지 않는다(열 때 만들고, 닫으면 렌더러째 없앤다).
- **닫기·끝내기 직전 저장**: 큰 창을 닫거나 앱을 끝내면 메인이 각 창에 '쓰던 글 저장'을 요청하고 기다린다(0.8초까지). 입력은 0.5초 뒤 저장되므로, 그 사이에 닫아도 남는다.
- **기타 정리**:
  - DB 연결(`desktop/db.cjs`) 준비 문장 캐시는 200개 상한(LRU)으로 둔다. 예전에는 BEGIN·COMMIT마다 캐시를 통째로 비웠다.
  - 창이 트랜잭션을 연 채 죽으면 메인이 되돌린다.
  - 쓰지 않던 `todos_due` 인덱스를 없앴다(EXPLAIN 확인).
  - 인기 테마색은 설정의 추천 줄이 보일 때만 받는다(미니창·시작 때 받지 않음).

- **데이터 폴더 옮기기 고침**(`desktop/userdata.cjs`):
  - `--user-data-dir`로 켠 측정 프로필에서도 예전 기본 폴더(`%APPDATA%\naegirok-desktop`)를 그 프로필 자리로 옮겨 버리던 문제를 고쳤다.

### 마이그레이션·백업·복구

- **로컬 DB 스키마**: 버전은 5 그대로. 열 변경은 없고 `DROP INDEX IF EXISTS todos_due`만 했다(몇 번 실행해도 같다).
  - 예전 구조(v3·v4)에서 옮기는 것은 `repo.test.ts`가 확인한다: 행 내용 그대로, 보내지 못한 변경 유지, 새 열을 채우려 한 번 처음부터 다시 받기.
- **PC 자동 백업**: 스키마 버전이 오르는 업데이트를 처음 켤 때, 고치기 전에 `<데이터 폴더>\backups\naegirok-v<예전 버전>-<시각>.db`로 통째로 복사한다(`VACUUM INTO`, 최근 3개).
- **되돌리기**:
  1. 앱을 끈다(트레이 → 종료).
  2. `naegirok.db`, `naegirok.db-wal`, `naegirok.db-shm`을 다른 곳으로 옮긴다.
  3. 백업 파일을 `naegirok.db`로 복사한 뒤 켠다.
  - 계정에 로그인해 있으면 서버의 최신 내용이 다시 내려오고, 백업 뒤에 이 기기에서 고친 것은 사라진다.
- **손으로 백업**: 설정 → ⋯ → 백업(JSON 내보내기·가져오기, 같은 id는 늦게 고친 쪽, 휴대폰·PC 같음). PC는 앱을 끈 채 데이터 폴더의 `naegirok.db*`를 복사해도 된다.
- **서버**:
  - 스키마 변경은 없다(응답에 `foreign_digest`·`foreign_same` 추가).
  - 서버는 켜질 때 `schema.sql`을 통째로 실행한다(모두 `IF NOT EXISTS`·조건부).
  - 백업: `docker compose exec db pg_dump -U modo modo > modo-$(date +%F).sql`
  - 복구: `psql -U modo modo < 파일`

### 데이터 폴더 사고 (2026-10-18, 고침)

측정용 프로필을 처음 만들 때(`--user-data-dir=...\tpl-small`), 위의 옮기기 코드가 실제 데이터 폴더 `%APPDATA%\naegirok-desktop`을 그 프로필 자리로 옮겼고, 그 위에 측정용 데이터(폴더 3·할 일 12·메모 6)가 들어갔다.

- **잃은 것:**
  - kv의 `prefs`(꾸미기 설정)와 `session`(마지막 폴더·입력 초안)은 측정 데이터가 덮어써 원래 값을 찾지 못해 지웠다(앱 기본값으로 시작).

## 미검증 / OS별 제한

- **출시 전 성능 정리(2026-10-18)에서 직접 하지 못한 것**:
  - 실제 Windows 로그아웃·로그인으로 자동 실행되는 것. `--autostart` 인자로 흉내 냈고, 시작 프로그램 레지스트리 등록·해제·예전 항목 옮기기는 실제로 확인한 뒤 지웠다.
  - 휴대폰 큰 데이터 측정. 에뮬레이터가 Play 이미지라 앱 DB를 넣을 수 없었다. 할 때는 `<profileable android:shell="true"/>` 진단 빌드에 백업 JSON(큰 데이터)을 가져오기로 넣고 같은 표(`am start -W`, `dumpsys meminfo`, `dumpsys gfxinfo`, `/proc/<pid>/stat`)를 잰다.
  - 실기기 배터리. 위 worklets 매 프레임 루프의 실기기 영향은 미측정이다.
  - iOS 전부(빌드 환경 없음): 위젯의 루틴 기록·체크 풀기, 입력창 모드 아이콘의 키보드 동작.
  - PC 실행 파일 아이콘·이름: Electron 그대로면 탐색기·작업 표시줄·시작 프로그램에 원자 모양 아이콘과 'Electron'이 보인다. `desktop/scripts/win-exe.cjs`가 modo.exe에 modo 아이콘(`assets/icon.ico`, 16~256 — `scripts/make-icon.py`가 로고 선 경로에서 크기마다 8배로 그려 줄인 둥근 사각형, 16~24px은 선을 조금 굵게)과 이름(설명·제품 이름 modo)을 넣는다 — electron-builder `afterPack`으로 자동, 이미 풀어 둔 폴더는 앱을 끈 뒤 `node scripts/win-exe.cjs <modo.exe>`. rcedit(signAndEditExecutable)은 Linux에서 wine이 있어야 해서 쓰지 않는다. 미니창·큰 창도 같은 .ico를 창 아이콘으로 쓴다. 시작 프로그램 레지스트리 값 이름(`electron.app.Electron`)은 그대로다(화면에 보이는 이름·아이콘은 실행 파일 정보).

- **iOS 전체 미검증**: macOS·Xcode가 없어 빌드·실행하지 못했다. Swift(위젯·잠금화면 위젯·제어 센터 버튼·리마인더)는 작성만 했고 `expo prebuild -p ios`로 프로젝트 생성(위젯 타깃·App Group 연결)까지만 확인했다.
- **Windows 일부 미검증**: 화면 캡처 권한이 없어(잠긴 화면) 창 투명 합성은 앱 자체 캡처로만 확인했다. 트레이 메뉴 조작, 로그인 시 실행의 실제 동작, 여러 모니터 이동은 직접 조작해 보지 못했다(좌표 보정은 화면 밖 좌표로 검증). 설치 프로그램(서명된 exe)은 만들지 않았다(zip 실행 폴더).
- **잠금화면 위젯**: Android는 4.2~4.4, 15 이상 태블릿, 16 QPR2(SDK 36.1) 이상 휴대폰에서 잠금화면 위젯을 지원한다. 휴대폰은 켜는 메뉴를 제조사가 열어 줘야 해서(Pixel: 설정 → 디스플레이 → 잠금 화면 → 잠금 화면의 위젯) 앱은 '쓸 수 있을 수도 있음'으로 안내하고 잠금화면 알림을 대안으로 둔다. 테스트 에뮬레이터(Android 16 QPR2 이미지)에는 이 메뉴가 없고 잠금화면을 밀어도 위젯 화면이 열리지 않아, 잠금화면에 놓인 위젯과 공개 범위 적용은 실제로 확인하지 못했다. 삼성 One UI가 다른 앱 위젯을 잠금화면에 허용하는지도 확인하지 못했다. 에뮬레이터에 화면 잠금(PIN)이 없어 '개수만'이 잠긴 화면에서 가려지는지도 미확인.
- **위젯·타일·알림에서 바꾼 내용**은 앱이 다음에 실행될 때 서버로 올라간다(Android가 백그라운드 앱을 얼리기 때문). 그 전에 앱을 지우면 그 변경은 사라진다.
- **리마인더**: Android 14+는 '정확한 알람' 권한이 기본으로 꺼져 있어 최대 10분 늦게 울린다(설정 화면에서 허용 안내). iOS는 예약 알림 64개 제한이라 가까운 60개만 둔다.
- **가로 폰 + 키보드**: Android가 전체 화면 입력 모드로 바꿔 목록이 가려진다(표준 동작).
- 폴더 구조 변경(폴더마다 메모 하나) 뒤에 다시 손으로 확인하지 못한 것: 한글 조합 입력(입력창 제출 로직은 바꾸지 않음), 공유받은 폴더의 보기 전용 화면(서버 권한·공유 E2E 테스트는 통과). '기본' 폴더는 폴더 행이 없어 공유할 수 없다(공유는 만든 폴더 단위).
- 위젯은 목록(스크롤) 대신 줄을 직접 그린다: 목록 위젯은 줄 안의 버튼마다 다른 동작(완료/고치기)을 걸 수 없어서. 대신 높이에 들어가는 만큼씩 쪽으로 나눈다.
- 홈 위젯은 Android·iOS 모두 가로 밀기 제스처를 받지 못해(Android RemoteViews에는 가로로 넘기는 뷰가 없고 목록형 뷰도 ListView 세로 스크롤·StackView 위아래 넘김뿐, iOS WidgetKit은 Button·Toggle(App Intents)과 Link만) 쪽 넘기기를 아래 점 누르기로 했다. 홈 화면에서 옆으로 밀면 런처가 화면을 넘기고 그 터치는 위젯의 누르기로 오지 않는다(에뮬레이터에서 메모·동그라미 위로 밀어도 읽기 모드·완료가 되지 않음을 확인). 폴더 바꾸기: 두 플랫폼 모두 앱처럼 메모 위 폴더 탭을 누른다(위젯 안에서 목록을 펼치는 조작은 지원되지 않아 탭으로 했다). 탭은 로고 오른쪽 같은 줄. iOS에서 처음 보일 폴더는 위젯을 길게 눌러 '위젯 편집'에서 고르고, 탭으로 고른 폴더는 (편집에서 고른 폴더, 크기)마다 저장된다. iOS 위젯 배경은 시스템이 그려 홈 화면이 비치지 않는다(시안의 반투명은 Android만). iOS는 위젯 하나하나를 가리키는 값이 없어 쪽·읽기 상태는 (폴더, 크기)마다 둔다: 같은 폴더·같은 크기 위젯 두 개는 쪽을 함께 쓴다. iOS 홈 위젯은 중간·크게만(작게는 머리 + 할 일 2줄 + 점 줄이 들어가지 않아 뺐다).
- 위젯 갱신은 시스템이 횟수를 제한해 다른 기기 변경이 늦게 보일 수 있다.

## 대표색

- 대표색 #85ADE2는 `app/src/brand.ts` 한 곳에서 관리한다. 기본 강조색(로고 심볼·체크·선택 탭·보내기 버튼)과 위쪽 그라데이션이 이 색에서 나오고, 다른 테마색을 고르면 앱 안 로고까지 그 색을 따른다(위젯 로고도 같다). 앱 아이콘·트레이·스플래시 그림은 늘 이 색.
- JS를 못 읽는 휴대폰 위젯은 같은 값을 따로 갖는다: Android `res/values/colors.xml`(modo_brand)·`SurfaceTheme.kt`(BRAND), iOS `Widgets.swift`(brand)·`expo-target.config.js`($accent). `src/__tests__/brand.test.ts`가 서로 같은지 확인하니 대표색을 바꾸면 테스트가 알려 준다. 앱 아이콘·트레이·스플래시 그림도 이 색으로 그려져 있어, 대표색을 바꾸면 그림도 다시 칠해야 한다(가장자리까지 같은 비율로 옮기면 된다).
- 예전 기본색(#72CDF4, #85ADE2 등, `prefs.ts`의 OLD_DEFAULTS)을 쓰던 설정은 불러올 때 대표색으로 바뀐다.

## 테마 동기화 · 인기 테마색

- 계정에 지금 쓰는 테마색(`users.theme_id`, `#RRGGBB`)을 둔다. 앱은 테마색을 바꾼 시각(`prefs.accentAt`)을 같이 기억하고, 로그인돼 있으면 `GET/PUT /api/me/theme`로 계정과 맞춘다(늦게 바꾼 쪽이 이긴다, 동기화 끝날 때 1분에 한 번까지 받아 온다). PC·휴대폰이 같은 테마를 이어 쓴다.
- 인기 테마색 `GET /api/themes/popular`: 지금 그 색을 쓰는 계정 수(계정당 한 표). 서버는 하루 한 번 순위를 새로 만들고, 앱도 하루 한 번만 받아 둔다(`kv.popular_themes`). 누가 어떤 색인지는 내보내지 않는다.
- 설정 첫 화면 꾸미기 줄의 추천 4색(`state/popularThemes.ts`): 맨 앞은 늘 기본 하늘색, 나머지 셋은 인기색(계정 30개 이상 모이고, 3명 이상 쓰는 앱 색 목록의 색만). 모자라면 꾸미기 첫 화면의 4색(파랑·차콜·화이트·주황, `MAIN_ACCENTS`, 전체 팔레트에도 있는 색)으로 채운다. 화면을 여는 동안 순서는 고정, 지금 쓰는 색이 추천에 없으면 마지막 자리에 보인다(꾸미기 첫 화면은 5번째로 덧붙인다). 더 많은 꾸미기의 전체 색 목록 순서는 바꾸지 않고 새 색(차콜)은 맨 뒤에만 붙인다. 채도가 0.2보다 낮은 색(회색·차콜·화이트·블랙, 살짝 푸른 회색 #A7B0BE 포함)은 회색 그라데이션(예전엔 #A7B0BE가 남색으로 나왔다).
